New tools for reading pages and emulating slow devices, more clients and browsers, and stricter safety options.

### Added

- `screenshot` accepts `maskPasswords: true` to cover visible password fields, including fields in shadow roots and cross site frames. Masking is best effort and reports a warning because page changes and secrets outside password fields can still expose content.
- `permissions` grants, denies or releases overrides for geolocation, notifications, camera, microphone and clipboard permissions for an origin. Conflicting session overrides are refused.
- `--cdp-log` records CDP message direction, method, numeric id and byte size for diagnostics without recording message contents.
- `tab_duplicate` opens the address of an owned tab in a new background tab, without copying its history or live page state.
- `page_extract` lists the links, headings, meta tags and forms of the top document of a tab, with the number of items found and a flag when a list was cut. Addresses have secrets in them hidden, the values of form controls are never read, and meta tags whose name looks like a secret show `[hidden]`.
- `find_in_page` finds visible text in the top document of a tab, also inside open shadow roots, and lists each match with its context and viewport position. With `scroll: true` it brings a match to the middle of the view without taking the focus; that is the only case that changes the page, so read-only mode refuses it.
- `emulate_cpu` requests CPU throttling by a factor from 1 to 20 and removes the override with a slowdown of 1 or `reset: true`. The browser controls scheduling, so the observed slowdown can differ from the requested factor. The daemon also applies the setting to existing and new cross site frames; a failure in an individual frame is logged without failing the call.
- `browser_info` reports the version, revision, real user agent, JavaScript engine version and protocol version of the connected browser, for bug reports.
- `safety.uploadDirs` (`--upload-dirs`, `CHROMIUM_DEVTOOLS_MCP_UPLOAD_DIRS`) limits `input_upload` to files inside the listed absolute directories. Symbolic links are resolved for the file and the directory. An empty list, the default, keeps the previous behavior. The tool and daemon both check the paths for sessions using this setting. Restricted uploads use opened directory handles and private copies to prevent path replacement from redirecting the browser. Copies remain available during the session and for at least 24 hours after a clean session close; later restricted uploads remove expired copies when possible. The configured directories must be trusted when opened, and processes that can change the private copies or the original file contents can still alter what the browser reads.
- The installer writes the server entry for Claude Desktop, Windsurf, Gemini CLI, VS Code and VS Code Insiders (`--client claude-desktop|windsurf|gemini-cli|vscode|vscode-insiders`). `--client all` still means the first four clients. These entries follow the locations the clients document and were tested with a fake file system, not inside the clients.
- `install --scope project` writes the entry into the current directory for Claude Code (`.mcp.json`), Cursor (`.cursor/mcp.json`) and VS Code (`.vscode/mcp.json`).
- `install --list` shows for every client whether the entry is installed, up to date or different, without writing anything.
- The `browser` setting accepts `chrome-beta`, `chrome-dev`, `chrome-canary`, `chromium` and `edge`, each with its install locations and user data directory. Only stable Chrome has been run against the server.
- `docs/troubleshooting.md` collects the common setup problems.

### Changed

- With `safety.allowPrivateNetworks` off, a public name is looked up before `new_tab`, `page_navigate` and `lighthouse_audit` open it, and again for the address a navigation ended on. The call is refused when the name resolves to a local or private address. The check is best effort: a name that does not exist or a lookup that fails is let through, answers in `198.18.0.0/15` (used by proxy and VPN tools) are ignored, and a name can still change its answer after the lookup.
- `localhost.localdomain`, `*.localdomain`, `ip6-localhost` and `ip6-loopback` count as local names.
- A running daemon of an older version rejects the new `safety.uploadDirs` setting; stop it with `daemon stop` after updating.
- `input_upload` reports whether the browser accepted the file selection command and whether the input still contains the requested number of files. When the selection cannot be confirmed in the input, check the page before retrying: it may already have processed the files. Verified with an attachment in Mail.ru, which clears the input after accepting the file.

### Fixed

- Managed browser reuse checks a private profile identity record, preventing an unrelated browser from being selected by a debug port or copied `DevToolsActivePort` file.
- Case insensitive page search handles text whose lowercase form has a different length.
- Installer backups use unique names instead of overwriting earlier backups made in the same second.
- Concurrent installer runs for the same resolved configuration path are refused to prevent lost changes.
- Event subscriptions remain independent, and handlers removed during event delivery are not called after removal.
- Cancelling a pending tab event subscription no longer restores its listener after attachment finishes.
- Closing a tab or session removes child frame listeners even when frame attachment finishes later.
- A child frame attaching during an unsuccessful tab close still receives event subscriptions and emulation settings.
- CDP close subscriptions can be registered independently and removed during notification.
- A close callback that closes the CDP client again no longer closes the transport twice.
- Daemon shutdown waits for sessions already closing and for isolated contexts still being created to be cleaned up, including during reentrant shutdown.
- A failure to dispose an interrupted isolated context is reported without exposing browser error details.
- If an older daemon rejects a new session setting, the client reports how to stop it and retry, and warns about disconnecting clients, closing session-created tabs and isolated contexts, and stopping a managed browser it started.
- CLI help lists `--upload-dirs` and the installer `--scope` option.
- Unsubscribing during iframe attachment no longer restores the event listener, and a detached iframe is not restored from a late frame tree response.

- A rejected iframe auto attach request cleans up its listeners and child sessions.
- File upload results report the target file name when the supplied path is a symbolic link. Restricted upload copies are removed when the browser explicitly rejects the attachment.

- Local builds make the CLI executable on macOS and Linux, including when a client invokes it through a symbolic link.
- A domain rule written as a numeric or IPv6 address in another form, such as `127.1` or `[0:0:0:0:0:0:0:1]`, never matched the address in its usual form, so a `safety.deniedDomains` entry written that way did not block it. Rules are now compared in the canonical form, and a numeric rule that is not a valid address is rejected at startup.
- `input_upload` no longer reports a false failure when a page consumes a file and clears or removes the input. A browser accepting the selection does not prove that the site completed the upload.
- `page_extract` checks all meta name attributes for secrets and hides content when any name is too long to inspect fully. It also returns up to 50 controls per form independently of the list `limit`.
- Browser WebSocket addresses no longer appear in connection errors, daemon settings or configuration mismatch messages.
- A failed request to stop a performance trace no longer discards the recording state or releases its lock, so the same session can retry.
- Permission changes now obey private network rules in the daemon. If a reset or session cleanup fails, the daemon reports the failure and retries pending cleanup before another permission change in that context.
- Changing the emulated geolocation origin no longer silently ignores a failure to release the previous permission.
- The trace test waits for the layout shift before stopping the trace, so it no longer fails on a busy machine.
- CPU emulation tests compare longer observable workloads and clean up their overrides after failures.
- Development tooling uses a patched `minimatch` version; npm audit reports no known vulnerabilities in the dependency tree.
- The package smoke check works with spaces in Windows temporary paths.

- Resolved private addresses are checked for permission changes at the daemon boundary as well as the tool boundary.
- Permission overrides are released when isolated context disposal fails.
- Geolocation permissions stay consistent when tabs change or close concurrently.
- Permission overrides can be released after an origin changes its DNS address.
- A CDP request is recorded as sent only after the transport accepts it.
- A new geolocation permission is not granted after cancellation.
- Geolocation permission cleanup is retried after a tab closes if Chrome temporarily rejects it.
- The previous permission is restored if a geolocation reset fails or is cancelled.
- Failed geolocation rollback is reported, and failures that finish after cancellation are logged.
- Upload directory restrictions apply to direct daemon file attachment requests.
- CPU emulation tests verify that the cross site frame is attached before measuring.
- Restricted upload contents remain available after the original path is replaced, and unused copies are cleaned up on cancellation.
